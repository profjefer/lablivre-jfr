1. Visão Geral e Arquitetura

O LabLivre é uma suíte de automação em Shell Script para gestão centralizada de laboratórios GNU/Linux. Permite que um único nó (a máquina do professor) orquestre dezenas de terminais clientes via SSH — sem instalar nenhum software nas máquinas dos alunos.

🎯 Princípios de design
  • Stateless / agentless: zero software instalado nos clientes
  • Fileless execution: comandos rodam na RAM remota, sem cópia de arquivos
  • Zero-Config: auto-detecta a sub-rede ativa em qualquer laboratório
  • DRY: credenciais e parâmetros centralizados em configs/lablivre.conf
  • Observabilidade: 5 dashboards web reativos consumindo um api.json único
  • Rastreabilidade: toda ação destrutiva registrada em JSON estruturado

Componentes principais

menu.shInterface texto (orquestrador principal)
xmenu.shInterface gráfica via Zenity

2. Instalação

Opção A — Via pacote .deb (recomendado)

A forma mais profissional, ideal para implantação em múltiplos laboratórios:

sudo apt install ./lablivre_4.2.1_all.deb

O pacote cria o usuário do sistema, instala dependências declaradas, configura permissões, ativa o serviço web no systemd e cria o symlink global /usr/local/bin/lablivre.

Opção B — Via Git

git clone https://github.com/USUARIO/lablivre.git /opt/lablivre
cd /opt/lablivre
bash configurar_lab.sh

Opção C — Via tarball

tar -xzf lablivre-4.2.1.tar.gz
sudo mv lablivre /opt/
cd /opt/lablivre
bash configurar_lab.sh

Configuração inicial

O script configurar_lab.sh é interativo e cuida de:

  • Instalação de dependências (nmap, sshpass, zenity, wakeonlan, ethtool, dmidecode...)
  • Criação da estrutura de diretórios (configs/, logs/, web/)
  • Coleta de credenciais SSH dos clientes (usuário e senha)
  • Definição do nome do laboratório (LAB_NOME) e da pasta de material
  • Aplicação de permissões restritivas (chmod 600 no conf, 700 em configs/ e logs/)
  • Provisionamento das tarefas no cron e do serviço systemd do servidor web
⚠ Após instalar

Preencha o arquivo configs/macs.txt com os MACs e nomes amigáveis das máquinas do laboratório (uma linha por máquina). Depois execute a opção 1 — Mapear Rede do menu para gerar o ips_atuais.txt.

Atualizar para uma nova versão

Para atualizar, não é preciso remover a versão anterior. Basta instalar o novo .deb por cima — o dpkg faz o upgrade preservando suas configurações (lablivre.conf, macs.txt) e logs:

sudo apt install ./lablivre_4.2.1_all.deb

Se instalou via Git ou tarball, atualize com:

# Via Git
cd /opt/lablivre && git pull && bash _provisionar.sh

# Via tarball (extraia por cima, sem apagar configs/)
tar -xzf lablivre-4.2.1.tar.gz
sudo cp -r lablivre-4.2.1/* /opt/lablivre/
cd /opt/lablivre && bash _provisionar.sh

Remover o LabLivre

ComandoO que faz
sudo apt remove lablivreRemove o programa, mantém configs e logs em /opt/lablivre/
sudo apt purge lablivreRemove tudo, incluindo configurações, logs e a pasta /opt/lablivre/

Tanto remove quanto purge já cuidam de:

  • Apagar os atalhos lablivre e lablivre-gui de /usr/local/bin/
  • Desativar e remover o serviço lablivre-web.service do systemd
  • Remover as tarefas do LabLivre do cron do usuário operador
💡 Limpeza completa garantida

Se usou apt remove (não purge) e depois quiser apagar os dados restantes:

sudo apt purge lablivre
sudo rm -rf /opt/lablivre
🔁 Reinstalar do zero

Para uma instalação totalmente limpa (descartando configurações antigas):

sudo apt purge lablivre
sudo rm -rf /opt/lablivre
sudo apt install ./lablivre_4.2.1_all.deb

4. Arquivos de Configuração

configs/lablivre.conf

Ponto único de verdade para a configuração do laboratório:

LAB_NOME="old"                          # identifica o laboratório
LAB_USUARIO="ufpr"                       # usuário SSH dos clientes
LAB_SENHA="***"                          # senha (modo fallback)
LAB_PASTA_MATERIAL="envia_material"     # origem padrão
LAB_IDIOMA="pt_BR"                        # pt_BR | en_US

🔒 Importante

Este arquivo é automaticamente configurado com chmod 600. Nunca o comite num repositório público. Adicione ao .gitignore.

configs/macs.txt

Lista mestre de identidades, ancorada nos endereços MAC físicos. É obrigatória e feita por você — o LabLivre não gera este arquivo sozinho (pegue o MAC com ip link em cada máquina). 5. Requisitos das Máquinas Clientes

  1. Sistema: Ubuntu (testado em 22.04 e 24.04) ou derivado Debian compatível.
  2. Usuário SSH: um usuário administrativo padronizado em todas as máquinas, com a mesma senha (ou chave SSH equivalente).
  3. SSH habilitado: daemon sshd ativo e aceitando conexões na porta 22.
  4. Wake-on-LAN: habilitar na BIOS/UEFI e desativar Deep Sleep Control em desktops corporativos.
  5. Rede IPv4. O LabLivre trabalha somente com IPv4 (ver docs/ROADMAP.md).
  6. sudo sem senha em comandos específicos — será configurado automaticamente na 4.3. Até lá, quem quiser pode criar à mão um /etc/sudoers.d/lablivre (sempre com visudo -f):
softwarelivre ALL=(root) NOPASSWD: /usr/sbin/iptables, /usr/sbin/shutdown, /usr/sbin/dmidecode, /usr/sbin/ethtool, /usr/bin/timedatectl
ℹ Sem agente

Não é necessário instalar nada além do que o Ubuntu já traz. O LabLivre opera 100% via SSH e ferramentas nativas do sistema.

7. Dashboards Web e Observabilidade

Como acessar

# Na máquina do professor:
http://localhost:8080/

# De qualquer dispositivo na rede (celular, tablet, outro PC):
http://<ip-do-orquestrador>:8080/
⚠ Sempre via HTTP, nunca file://

Abrir os HTMLs diretamente (clicando no arquivo) faz o navegador bloquear o fetch('api.json') por política CORS. Use sempre http://localhost:8080/.

8. Auditoria Estruturada (JSONL) NOVO v4

Toda ação destrutiva — modo prova, distribuição de material, shutdown, manutenção, inventário — gera uma linha em logs/auditoria.jsonl no formato JSON estruturado:

{"ts":"2026-06-03T22:30:15","usuario":"ufpr",
 "host":"ufpr-OptiPlex-7010","acao":"modo_prova_ativar",
 "detalhes":{"maquinas_afetadas":"10"}}

Três formas de consultar

  1. Menu opção 11 — visualizador interativo com filtros por data, tipo de ação e últimas N entradas.
  2. Dashboard de auditoria — timeline filtrável em http://localhost:8080/dashboard_auditoria.html.
  3. Snapshot diário — todo dia às 23h59 o sistema consolida métricas em logs/historico.jsonl. Permite análises longitudinais (quantas provas no semestre, dias de maior uso, etc.).

9. Segurança: Senha vs Chave SSH NOVO v4.1

🔓 Modo Senha (padrão)

A senha SSH dos clientes fica em texto puro em configs/lablivre.conf, protegida apenas pelo chmod 600. Usa sshpass em runtime. Funciona em qualquer instalação sem setup prévio nas máquinas — ideal para implantação inicial.

🔐 Modo Chave (recomendado)

Um par Ed25519 é gerado em configs/lablivre_key e distribuído automaticamente para todas as máquinas via ssh-copy-id. A senha em texto puro deixa de ser usada na operação normal, permanecendo apenas como fallback para máquinas novas.

Vantagens: zero sshpass em runtime (senha não aparece em ps ou logs do sistema), chave revogável, qualitativamente mais seguro.

Como migrar para modo chave

  1. Garanta que o configs/lablivre.conf está configurado e funcional (modo senha)
  2. Execute a opção 1 — Mapear Rede para listar máquinas online
  3. Execute a opção 12 — Configurar Chave SSH
  4. O script gera, distribui, valida e ativa o modo chave automaticamente
  5. O cabeçalho do menu passa a mostrar 🔐 Chave SSH

Quando máquinas novas entrarem no laboratório, basta rodar a opção 12 novamente — o script detecta quem já tem a chave e só configura as faltantes.

Voltar para modo senha

Edite configs/lablivre.conf e troque:

LAB_AUTH_MODE="chave"  →  LAB_AUTH_MODE="senha"

🔥 Mapa de Calor (gerar_mapa_calor.sh)

A cada mapeamento de rede (manual ou via cron horário), o sistema também registra uma linha por máquina em logs/historico_maquinas.jsonl. Esse acúmulo alimenta o dashboard Mapa de Calor que mostra quais máquinas são mais utilizadas no laboratório.

Como funciona

  1. Cada execução do atualizar_ips.sh registra {"ts","mac","nome","ip","status"} para cada máquina
  2. gerar_mapa_calor.sh agrega por MAC e calcula a frequência relativa de cada máquina
  3. O resultado vai para web/mapa_calor.json
  4. O dashboard web/mapa_calor.html consome o JSON e classifica em 5 níveis:
NívelFaixa de usoCor
🔥 Hot80–100% do máximoVermelho
🌶️ Warm60–79%Laranja
☀️ Mild40–59%Amarelo
❄️ Cold20–39%Azul claro
🧊 Frozen0–19%Azul escuro

O histórico é limitado a aproximadamente 30 dias (10080 registros considerando varredura horária) para evitar crescimento ilimitado.

💡 Utilidade prática

Permite identificar:

  • Máquinas subutilizadas (candidatas a remanejamento)
  • Máquinas com problema (sempre offline = falha ou WoL desligado)
  • Padrões de posicionamento preferido dos alunos

11. Comandos Core e Técnicas Internas

Auto-detecção de rede (Zero-Config)

# 1. Identifica a interface ativa
IFACE=$(ip route | awk '/default/ {print $5}' | head -1)

# 2. Extrai CIDR exato
REDE=$(ip -o -f inet addr show dev "$IFACE" | awk '{print $4}')

# 3. Varredura em camada 2 (ARP ignora firewall do alvo), em cascata:
sudo arp-scan --interface="$IFACE" --localnet   # preferido
sudo nmap -sn -PR "$REDE"                       # alternativa
ping (sub-rede inteira) + ip neigh                # sem root, último recurso
# Se ninguém responder (nem o roteador), o ips_atuais.txt anterior é mantido.

Execução fileless via SSH

# Heredoc com aspas simples impede expansão local de variáveis (segurança)
PAYLOAD=$(cat <<'EOF'
echo "CPU: $(grep -m1 'model name' /proc/cpuinfo | cut -d: -f2)"
EOF
)
echo "$PAYLOAD" | ssh_remote_stdin "$ip" "bash"

Wrapper SSH unificado (chave ou senha)

# modulos/_ssh.sh decide automaticamente o modo
ssh_remote() {
  if [ "$LAB_AUTH_MODE" = "chave" ]; then
    ssh -i "$CHAVE_SSH" "$LAB_USUARIO@$ip" "$cmd"
  else
    sshpass -p "$LAB_SENHA" ssh "$LAB_USUARIO@$ip" "$cmd"
  fi
}

Tar-Pipe Stream (distribuição de material)

# Empacota local, transmite via SSH, extrai remoto — sem arquivos intermediários
tar -cf - -C "$DIR_PAI" "$NOME" | ssh_remote_stdin "$ip" \
  "tar -xf - -C ~/Área\ de\ Trabalho/Material"

Modo Prova (iptables, cadeia própria)

✅ Persistente e com validade (4.2.1)

O serviço lablivre-prova.service reaplica as regras no boot — reiniciar não derruba a prova. Um timer desfaz o bloqueio ao fim da validade escolhida, e uma máquina ligada depois do prazo se desativa sozinha. Somente IPv4. Detalhes em docs/MODO_PROVA.md.

13. Troubleshooting

"Dashboards aparecem em branco / 'Carregando...' permanente"

Provavelmente você está abrindo o HTML via file:// (clique duplo). Use sempre http://localhost:8080/. Verifique também:

sudo systemctl status lablivre-web.service
curl -s http://localhost:8080/api.json | head -5

"xmenu.sh: Esta opção não está disponível"

Versões antigas do Zenity usavam --icon=, mas o Zenity 3.42+ renomeou para --window-icon=. Atualize para v4.1.3 ou superior — o problema está corrigido.

"SSH consome só a primeira máquina do laço"

Acontece com tail | while. Use sempre while ... done < <(tail).

"Modo prova ativou mas máquinas continuam com internet"

  1. Use a opção 3 → 3 (Ver situação real): ela pergunta a cada máquina se a regra está ativa.
  2. Na máquina do aluno: sudo iptables -S LABLIVRE_PROVA e systemctl status lablivre-prova.
  3. Confira se a rede entrega IPv6: ip -6 route show default. O Modo Prova é somente IPv4.
  4. A máquina ligou depois da ativação? Use 3 → 4 (Reaplicar).

"atualizar_ips não encontra máquinas"

  1. Confirme que configs/macs.txt está preenchido (MACs válidos; a opção 1 avisa os inválidos/duplicados)
  2. Veja a linha Método: na saída. ping+arp (sem root) indica que o sudo local falhou — a opção 1 pede a senha local se a LAB_SENHA não servir
  3. Instale o arp-scan (sudo apt install arp-scan) e veja a saída bruta em logs/atualizar_ips_*.log
  4. Máquina no wifi: cadastre o MAC wifi com o mesmo nome. Se o wifi estiver em outra sub-rede, ela não é visível por ARP

"Sincronizar horário falha em todas"

Rode a opção 16 e veja a coluna de cada máquina. [AJUSTADO] significa que o NTP não funcionou ali e o relógio foi acertado pela hora do orquestrador — confira se o próprio orquestrador está com NTP sincronizado (timedatectl). sudo recusou a senha indica LAB_SENHA errada.

"Esqueci a senha do lablivre.conf"

sudo cat /opt/lablivre/configs/lablivre.conf
# OU re-execute o wizard:
cd /opt/lablivre && bash configurar_lab.sh

"Quero ver tudo que aconteceu no lab"

cat logs/auditoria.jsonl | jq .
# OU pelo dashboard:
# http://localhost:8080/dashboard_auditoria.html
